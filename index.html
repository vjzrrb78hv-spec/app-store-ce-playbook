Keeping Subscribers — Checklist

  • Send notifications
  • Provide support
  • Let people manage subscriptions themselves
  • Extend renewal date — up to 2x/year, max 90 days
  • React to voluntary churn
  • Use Billing Grace Period
  • Price increase requires consent (offer expires if no response)

💲 Increasing the Standard Price — Applying to Existing Subscribers

Example: a price move from $1.99/$2.99 up to $3.99 can be phased so existing subscribers are migrated on a schedule while new subscribers see the new price immediately.

Use this to stagger price increase consent requests across subscriber cohorts rather than all at once.

Payment Options in the EU EFFECTIVE 1 OCT 2026

What Changes

  • Apps can offer alternative payment methods/processors alongside IAP
  • Chosen payment setup must stay consistent for 12 months
  • IAP must be presented at the same time as any alternative option shown in-app or via out-of-app actionable links
  • IAP must be displayed at least as prominently as any alternative
  • Different prices/benefits are allowed for alternative options
  • App Store product page may not mention alternative payment options

Requirements for Developers

  • StoreKit External Purchases/Offers Entitlement required
  • Must use ExternalPurchaseCustomLink API when offering alternative processing in-app or directing users out via actionable links
Reference: Apple Developer Program License Agreement governs the terms.

Design Principles HIG ESSENTIALS

Agency

  • Let people work their own way, at their own speed
  • Offer forgiveness — allow undo
  • Avoid disaster

Responsibility

  • Act in people's interest
  • Privacy: ask only for necessary data, explain why
  • Ask "how could this be misused?"

Familiarity

  • Build on what people already know
  • Use metaphor
  • Be consistent — same look, same behavior

Flexibility

  • Let people personalize
  • Support unique usage patterns

Simplicity

  • Simple ≠ minimal
  • Frictionless & intuitive; respect time
  • Clear visual hierarchy

Craft & Delight

  • Care about every detail; maintain design over time
  • Make it satisfying and human

💡 Designing for Subscription Success

Effortless
  • Be visible — not an ad, not a notification
  • Remove friction; watch click-to-conversion
  • Ask for personal info afterwards
Transparent
  • Clear name, price, value proposition
  • Strong CTA + Login/Restore options
  • Always offer multiple tiers + T&Cs
Engaging
  • Free trial / premium feature try-before-you-buy
  • Sample content (e.g. 10 free articles)
  • Family Sharing → growth, engagement, lower churn, higher CLV

App Review Guidelines Cheat Sheet 5 PILLARS

The full guidelines run 28 pages — here's what actually trips up large developers. Click to expand each pillar.

1 · SAFETY Objectionable content, kids, physical harm, data security
  • No defamatory/discriminatory content, realistic violence, or overtly sexual material
  • User-generated content requires: content filter, report mechanism, block-abusive-users, published contact info
  • Kids Category: no links out / purchases / distractions without a parental gate; no 3rd-party ads/analytics that collect identifiable data on kids
  • Medical/health apps: must disclose accuracy methodology; can't claim to measure vitals from sensors alone; must remind users to consult a doctor
  • Must have accurate, reachable developer contact info
Flag for BD: Escalating "user-generated content" complaints or health-claim apps early — these get greater scrutiny and slower reviews.
2 · PERFORMANCE Completeness, metadata accuracy, hardware & software rules
  • App must be final, functional, with working demo account/mode + backend live during review
  • Screenshots/previews must show real app in use — no misleading marketing
  • App name ≤ 30 characters; no keyword stuffing, no pricing/terms in metadata
  • Metadata (icons, screenshots) must fit 4+ rating even if app itself is rated higher
  • Apps must use public APIs only, run on current OS, be self-contained (no dynamic code execution/download)
  • No IPv6-only network failures; ads confined to main binary (not extensions/widgets/Kids apps)
Flag for BD: "Whats New" notes must specifically describe new features/product changes — generic text only OK for bug fixes.
3 · BUSINESS In-App Purchase, subscriptions, alternative payment paths
  • Must use IAP for: unlocking features, subscriptions, in-game currency, premium content — no license keys, QR codes, crypto workarounds
  • Subscriptions: min. 7-day period, ongoing value, must work across all user devices; upgrade/downgrade must be seamless
  • Exceptions allowed to skip IAP: Reader apps (magazines/books/audio/video — link-out entitlement available), Multiplatform services, Enterprise services, Person-to-person real-time services, Goods/services consumed outside the app, Free standalone companion apps, Ad-campaign management apps
  • External Purchase Link Entitlement / Music Streaming Services Entitlement — region-specific link-outs to developer's site, subject to strict conditions (US storefront has fewer restrictions)
  • No forcing users to rate/review/download other apps to unlock functionality
  • No manipulating rankings, reviews, or engaging paid/fake feedback
Flag for BD: This is the section developers push back on most — know 3.1.3(a)–(g) exceptions cold when advising on monetization strategy.
4 · DESIGN Originality, minimum functionality, spam, extensions
  • No copycat apps/icons/names — Apple treats impersonation as a Developer Code of Conduct violation
  • App must offer more than a repackaged website; no pure content-aggregator/marketing apps
  • No multiple Bundle IDs for the same app (e.g. one per city) — use IAP for variants instead
  • Certain categories (dating, flashlight, wallpaper, timers) need meaningfully different value to be accepted as new submissions
  • Keyboard/Safari extensions have specific functional requirements (e.g. must work offline, no launching other apps)
  • Login: if using a 3rd-party/social login, must also offer a privacy-respecting equivalent (unless exempt, e.g. own account system)
5 · LEGAL Privacy, IP, gambling, VPN/MDM
  • Privacy policy required everywhere (App Store Connect + in-app): what's collected, how, shared with whom, retention/deletion process
  • Consent required for data collection (even "anonymous"); no dark patterns forcing consent; data minimization — request only what's needed for core function
  • Account deletion must be offered if account creation is offered
  • Health/fitness data: can't be used for ads/marketing; can't write false data into HealthKit; human-subject research needs consent + ethics board approval
  • Kids privacy: COPPA/GDPR compliance; no 3rd-party analytics/ads for kids-primary apps
  • IP: only use content you own/license; no Apple product impersonation, no unauthorized Apple Music/emoji use
  • Gambling/lotteries/real-money gaming: must be free, geo-restricted, fully licensed per territory
  • VPN/MDM apps: NEVPNManager API only, org-enrolled developers only, no data resale, clear pre-use data disclosure
Flag for BD: Privacy policy gaps and consent flow issues are the most common source of repeat rejections for larger developers.

After Submission — Timeline

  • Repeated same-guideline rejections → slower future reviews
  • Future release dates: up to 24h to appear on all storefronts

Expedite / Appeals

  • Expedited review: only for genuine critical timing issues
  • Appeals available if developer disagrees with outcome

Bug Fix Exception

  • Bug fixes on live apps won't be delayed over guideline violations — except legal/safety issues
